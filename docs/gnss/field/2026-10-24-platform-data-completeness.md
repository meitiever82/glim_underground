# 平台组录制数据 vs 自录数据差异清单（驱动修改需求）

- 日期：2026-10-24
- 对比对象：平台组 `/Documents/Datasets/tage/zhongmei/`（1206/1250 两车，Foxglove mcap） vs 自录红沙泉 bag（ROS2 db3）
- 用途：给平台组改驱动用。定位/建图算法（紧耦合融合、地图质量评估）的输入需求以自录 bag 为基准

## 差异总表

| # | 项 | 平台组 mcap | 自录 bag | 影响 |
|---|---|---|---|---|
| 1 | **IMU** | **完全没有**（GpsRawData 里 acc_x/acc_y 是整车加速度标量，无角速度） | /cgi610/imu 100Hz 陀螺+加计原始值，/jt128/imu 雷达自带 IMU | **致命**：紧耦合融合没有 IMU 做不了 |
| 2 | **RTK 状态** | gps_rtk_status 恒 = 0xFFFFFFFF（无效占位） | /cgi610/fix 含 NavSatFix status，综导消息含 Position Type | 无法区分 FIX/FLOAT/单点，所有质量门失效 |
| 3 | 卫星数 | gps_satellite_front/rear 恒 = 0 | 有 | 无法判断观测质量 |
| 4 | 定位精度 sigma | 无 | 综导 sigma_enu（ENU 三向自报精度） | 因子图权重无法数据驱动 |
| 5 | 激光帧率 | 10Hz（实测帧间隔 0.10s，30s 分片×~290 帧） | 10Hz | ✅ 无差异 |
| 6 | 激光点格式 | 7B/点 int16-cm 有损打包（±327m 量程、1cm 量化、无 ring、**无每点时间戳**） | 22B/点 float32 xyz + intensity + ring + 每点时间戳 | 无法 deskew（运动畸变校正）；1cm 量化在远距等效角分辨率损失 |
| 7 | 外参 | 无 tf | /tf_static 全量传感器安装关系 | 多传感器融合缺刚体变换 |
| 8 | 容器格式 | Foxglove protobuf mcap | ROS2 CDR db3 | 需转换器（已写 mcap2ros2.py，可用但多一道工序） |
| 9 | 时间戳 | gps_ntime 比 mcap log_time **滞后 ~0.2s**（实测中位 +0.20s，p95 +0.30s）——GPS 管线延迟；激光只有 log_time（帧首/帧尾不明，±0.1s 歧义），与 GPS 钟域偏差实测 -0.35s 但曲线平坦（亚秒级、定不准） | header 统一接收机时标 | 合计可达 ~0.5s 级错位（6m/s 下 ~3m），融合必须补偿；仿真数据另有 ~9s 偏差（仿真特有） |

## 需要平台组配合的驱动修改（按优先级）

1. **【最高优先】IMU 原始数据回传**：610 的陀螺仪+加速度计原始输出（100Hz 级别）。设备本身在输出 INSPVA（gps_yaw/pitch/roll 有真值证明 INS 在跑），缺的只是驱动把 IMU 原始量录下来。
2. **RTK 状态透传**：610 的 Position Type（NARROW_INT=50 FIXED / NARROW_FLOAT=34 等）如实写进 gps_rtk_status，不要用 0xFFFFFFFF 占位。
3. **卫星数 + 定位 sigma 透传**：卫星数、差分龄期、水平/高程自报精度。
4. **激光点格式补时间信息**：至少给帧起始/结束时间戳，最好恢复每点时间戳（deskew 用）。（帧率 10Hz 实测正常，无需改）
5. **tf_static 外参随包落盘**（一次性常量，每包一条即可）。
6. **时间同步**：硬件时间同步（PTP/秒脉冲）暂不可行（平台限制，已确认）。软件侧补偿路线：
   - 短期：每个数据包离线标定一次固定钟差（轨迹形状匹配法已验证可用，中煤数据实测约 -0.35s），融合时按标定值平移时间轴；
   - 中期：钟差 td 作为参数进因子图在线估计（车速激励下可观，文献有成熟做法）；
   - 激光每点时间戳（deskew 用）仍建议驱动补上——与钟差无关，是帧内时序问题。

## 备注

- 有效字段（不用改）：经纬高、yaw/pitch/roll、ve/vn、车速——INSPVA 位置姿态链路是通的，证明只需补字段透传，不需要换硬件链路。
- 转换器已有：`glim_ws/mcap2ros2.py`（mcap → ROS2 bag），格式问题（#8）已工程解决；其余 #1-#7 是数据内容缺失，只能驱动侧补。
